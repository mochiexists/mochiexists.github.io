cmux · the fork

cmux Mochi

A fork of cmux, tuned for living inside agent-driven terminal work — resuming sessions, finding your files, watching the machine, and keeping the browser out of the way.

v0.64.151 · built on current upstream · mochiexists/cmux-mochi

Agents & sessions

Resume where you left the agent

Quit with Claude or Codex running, and on reopen cmux Mochi pre-types the exact resume command — you press Enter to continue. Or set it to auto-run, or to start fresh. Per-pane and deterministic, so the right session comes back to the right tab.

Settings → Terminal · default Medium

Scrollback that carries over

The restored pane keeps the agent's previous scrollback, so reopening a window looks exactly like you left it instead of a blank shell — even for live TUIs that were never formally detected as an agent.

Codex close-and-resume

Detaching from a Codex thread is treated as a real session end, cleanly staging the resume — and the resume command only appears once Codex has actually saved the session, so a thread you never prompted won't hand you a dead session id.

Tabs & navigation

Reveal in Finder · Copy Path

Right-click any tab. A terminal reveals its working directory, a markdown pane reveals the file, and a browser on a local file:// page reveals that file — selected in Finder, not just its folder.

right-click tab → Reveal in Finder

Reopen Closed Tab — with its scrollback

An accidental close comes back as the tab you actually had: its scrollback and last command restored, not an empty pane in the same slot.

⌘⇧T

Sidebar spring-load

Drag a session onto a collapsed workspace and it opens immediately, so you can drop the session right where it belongs — no pre-navigating.

Confirm before you quit everything

A tab-close that would take down the last pane and the whole window asks first. One stray ⌘W can't end the session.

Monitoring

A real Task Manager

Open it as a tab or a full-area page, with per-process CPU and memory — so when an agent or a build pegs the machine, you can see exactly what's responsible without leaving cmux.

Always-on CPU & memory footer

A persistent system-load readout pinned in the sidebar footer. Ambient, always there, catching the spike before you go looking for it.

Browser

One switch for "open it externally"

Right-click the New Browser button and flip Open in External Browser. It drives the global in-app-browser setting, so every web open — the button, an agent or CLI running open, a ⌘-clicked link — goes to your system browser. One control, not two that disagree.

Each of these is a self-contained change on top of current upstream cmux — written to be offered back. If your team uses cmux and any of it looks useful, it's yours: mochiexists/cmux-mochi.
